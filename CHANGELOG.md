## [Unreleased]

### Added
- **Backend Foundation (Phase 2)**:
  - SQLAlchemy 2.0 ORM data models covering all 17 tables from SRS Section 15.
  - Alembic configuration with initial autogenerated migration (`initial schema`).
  - Centralized application settings with Pydantic BaseSettings.
  - Base FastAPI application skeleton with CORS, custom exception handlers, slowapi rate limiting, and `/health` endpoint.
- **Authentication & Account Management (Phase 3)**:
  - User registration (`POST /api/v1/auth/register`) with case-insensitive unique email and username validation (FR-001, FR-002, FR-003, FR-012).
  - Argon2 password hashing (NFR-006) and token rotation with SHA-256 hashed refresh tokens.
  - User login (`POST /api/v1/auth/login`) supporting both email and username with generic error messages (FR-004, FR-005, NFR-007).
  - Refresh token rotation (`POST /api/v1/auth/refresh`) with reuse detection and session invalidation (FR-006).
  - Device session management (`POST /api/v1/auth/logout`, `POST /api/v1/auth/logout-all`, `GET /api/v1/auth/sessions`) (FR-007).
  - Centralized data isolation and authentication dependency (`get_current_user`, `get_user_record`, `user_scoped_query`) (NFR-002).
  - User profile retrieval (`GET /api/v1/me`), dynamic username changes (`PATCH /api/v1/me/username`) (FR-008), and account deletion with cascading cleanup and group succession (`DELETE /api/v1/me`) (FR-011).
- **Wallet, Opening Balance, Transactions & Categories (Phase 4)**:
  - Opening balance setup and editing with whole-rupee validation (minimum ₹100) and balance non-negative constraint checking (FR-009, FR-010, FR-020, FR-022).
  - Starter category seeder initializing 15 expense categories and 7 income categories with subcategories from Appendix A upon wallet creation (FR-030).
  - Category management with max 1 level of nesting, rename support, and deletion protection for "Shared" and "Other" or in-use categories (FR-031, FR-032).
  - Transaction operations (create, filter, search, sort, pagination, update, delete) with atomic row locking on wallets, future date rejection, and balance exhaustion protection (FR-023, FR-024, FR-025, FR-026, FR-028).
- **Budgets, Savings Goals & Recurring Transactions (Phase 5)**:
  - Overall monthly budget with automatic month-to-month carry-forward calculation for unused funds (FR-040, FR-043).
  - Category-level budgets with sum constraints enforcing that the category budget sum cannot exceed the overall base budget (FR-041, FR-042).
  - Automatic threshold budget notifications firing at most once per month at 80% and 100% spending (FR-045, FR-046).
  - Savings goals with fund contributions and withdrawals directly linked to wallet balances and completion alerts (FR-053, FR-054, FR-055).
  - Monthly recurring transaction rules with calendar day clamping, balance-insufficient skip logic, idempotency via run tracking, and catch-up on login (FR-048, FR-049, FR-050, FR-051, FR-052a, FR-052b).
  - Daily internal cron endpoint (`POST /api/v1/internal/jobs/daily`) secured with `X-Cron-Secret` header for automated recurring execution, 7-day split expiry, and 90-day notification pruning (FR-052b, FR-067, FR-081, NFR-009).
- **Bill Splitting, Groups & User Blocking (Phase 6)**:
  - Bill splitting with exact, percentage, and shares calculation modes, plus explicit remainder bearer assignment for whole-rupee remainder resolution (FR-060, FR-061, FR-062).
  - Full bill upfront expense creation for payer with wallet balance verification (FR-060).
  - Atomic split acceptance in a single database transaction with deterministic row locking on both wallets, participant balance verification, "Shared" expense creation, and payer bill reduction (FR-065, NFR-010).
  - Split lock invariant upon first participant acceptance and cancellation/edit guards (FR-068, FR-069).
  - Permanent groups with invitation workflow, creator succession upon departure, and auto-deletion when empty (FR-073, FR-074, FR-075, FR-076, FR-077, FR-078).
  - User blocking preventing split requests and group invites with generic non-revealing error messages (FR-072).
- **Notifications (Phase 7)**:
  - Notification channel architecture with in-app storage for v1 (FR-080, FR-084).
  - Read/unread tracking, mark single read, mark all read, and unread count polling endpoint (`GET /api/v1/notifications/unread-count`, FR-080, FR-082).
  - System-wide event notifications for split bill invitations/acceptances/rejections/expiries, budget threshold warnings (80% and 100%), recurring rule executions/skips, and goal completion alerts (FR-083).
- **Dashboard & Transaction Exports (Phase 8)**:
  - Central dashboard endpoint (`GET /api/v1/dashboard`) aggregating wallet balance, current month income vs expense, category donut breakdown, budget progress, recent transactions, goals progress, and 6-month historical trend (FR-090).
  - Multi-format transaction export supporting CSV, Excel (.xlsx), and PDF with custom filters for date range, category, and transaction type (FR-091, FR-092, FR-094).
  - ReportLab PDF generator rendering summary boxes (income, expense, net, count) and paginated transaction tables without charts (FR-093).
